# 2026-11-10 기록장 하나로 모으기

PKOS · 나의지식서재의 원본을 이 저장소 하나로 모았다. 개발 사본(pkem_new_real)에만 있던 기능을 합치고, 옛 기록장 주소와 사본을 정리했다.

## 들어간 것

- 게시 전 개인정보 검사(privacy-scan.js)와 ai-dx 지도 임시저장(aidx-link.js). 커밋 8b760e6.
- 빈 그림판에 직접 그리기(drawings-model.js, drawings.css), 창 바깥 눌러 닫기(dialog-dismiss.js).
- 게시 연결 주소. 서버 기능과 받는 화면(publisher-connect.*)은 개발 사본에 있었지만 주소를 만드는 곳이 없어서, 게시 설정에 「다른 기기에서도 게시하기」를 더하고 서버·화면 시험을 채웠다. 주소는 한 시간 안에 한 번만 쓰고, 고른 기록장 주소에서만 열린다.
- 런타임 커밋 5098381, 캐시 이름 pkem-real-shell-v52-unified.

- 단위 시험 110개 통과(게시 서버 17개 포함).
- 브라우저 시험 34개 가운데 29개 통과. 개인정보·임시저장 9개, 게시 연결 3개, 그림판, 창 닫기, 캡처, 미디어, 공유, 폴더 저장 등.
- 통과하지 못한 5개(blocks-desktop, database, workspace, panel-collapse, writing-ux)는 10-07~10-13 뒤 화면이 바뀐 것(「블록으로 편집」이 「도구 더 보기」로, 서식 단추 4개 제거, 속성 창 변경)을 반영하지 않은 옛 시험이다. 합치기 전 운영판(0628e17)에서도 같은 자리에서 실패하는 것을 확인했다. cloud 시험은 실행마다 결과가 달라(두 번째 실행 통과) 타이밍에 민감하다.

## 이어서 고친 것 (같은 날)

- 앱: 데이터베이스 「더 보기」와 블록 메뉴가 단추 오른쪽 끝에 맞춰 왼쪽으로 펼쳐지는데, 단추가 줄 앞쪽에 있으면(1200px 화면 등) 읽기 칸의 overflow:hidden 에 잘려 「CSV 저장」 같은 단추가 보이는데도 눌리지 않았다. 잘리는 쪽이면 오른쪽으로 펼치게 했다(app.js fitPopoverMenu). 1440·1920px에서는 예전처럼 왼쪽으로 펼쳐진다.
- 옛 시험 5개를 지금 화면에 맞췄다. 「블록으로 편집」은 「도구 더 보기」를 펼친 뒤 누르고, 블록 칸은 서식이 보이는 편집 칸(.block-rich)에 쓰고, 읽기 화면은 「저장하고 읽기」로 연다(blocks-desktop, workspace). 속성 창 이름(.db-modal [data-property-form]), 달력 항목이 상세 창을 여는 동작, 「더 보기」 안의 CSV 저장을 반영했다(database). 서식 단추 5개를 뺀 10-15 변경과 「그리기」 추가로 단추 수 기대값을 14→10, 13→9, 5→4로 고쳤다(panel-collapse, writing-ux).
- 흔들리던 시험 2개를 고쳤다. cloud는 다른 창의 동기화가 잠금을 쥐고 있으면 누른 동기화가 건너뛰어지는데 이전 「동기화됨」 문구를 보고 넘어갔다. 「동기화 중」을 거쳤는지 확인하고 건너뛰었으면 다시 누르게 했다(6회 연속 통과). desktop-workspace는 새로 고침 직후 행 수를 세던 것을 행 수가 맞을 때까지 기다리게 했다(3회 연속 통과).
