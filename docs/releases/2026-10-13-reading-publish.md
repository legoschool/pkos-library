## 사용 흐름

‘웹으로 공유하기’에서 기록과 첨부를 고르고 ‘포함 내용 미리보기’를 확인한 뒤 ‘웹에 게시하기’로 URL을 만듭니다. 받는 사람은 로그인 없이 읽습니다. 게시자는 ‘내가 게시한 문서’에서 같은 주소로 내용을 갱신하거나 게시를 취소하며 기존 ‘웹문서 ZIP 저장’도 유지합니다.

같은 주소를 갱신할 때는 ‘이 주소 갱신’으로 대상을 고르고 새 선택의 미리보기를 확인해 ‘선택한 주소 갱신’을 누릅니다. ‘게시 삭제’로 해당 주소의 게시를 취소합니다. 새 문서는 ‘새 주소로 게시’를 고릅니다.

기본은 글만 포함합니다. 첨부와 노트북 이름·태그는 별도로 고릅니다. 전체 서재나 휴지통을 자동 업로드하지 않으며 본문에 직접 적은 개인정보·외부 링크는 미리보기에서 확인합니다. 주소를 가진 사람은 공유본을 열 수 있고, 게시 취소는 이미 내려받은 사본까지 회수하지는 않습니다.

게시자만 최초 ‘게시 설정’이 필요합니다. 게시 권한 키는 별도의 로컬 활성화 파일로 제공하며 실제 키나 활성화 파일을 공개 소스·문서·공유 URL에 포함하지 않습니다. 읽는 사람에게 키를 요구하지 않습니다.

## 구현 범위

- 클라이언트: `reading-publish.js`에서 게시 준비·전송·결과 URL·관리 기능을 연결합니다.
- 게시 API: `api/reading-shares.js`에서 게시 권한 확인, 비공개 Blob 저장, 공유본 갱신·삭제를 처리합니다.
- 읽기 화면: `share.html`에서 공유 ID에 해당하는 묶음을 읽고 선택한 첨부를 표시합니다.
- 기존 읽기용 ZIP 내보내기는 계속 제공합니다. 원본 기록과 브라우저 백업의 용도는 바꾸지 않습니다.

Blob SDK 2.8.1의 비공개 저장소를 사용합니다. 읽기 본문은 DOMPurify로 정리한 뒤 스크립트를 허용하지 않는 `allow-same-origin` sandbox iframe에 표시합니다. HTML 등 실행 가능한 첨부는 `application/octet-stream` 다운로드로 제공합니다. 게시된 내용을 조회하는 응답은 `no-store`로 처리하고 게시를 삭제하면 같은 주소와 원문 API에서 더 이상 받을 수 없습니다.

## 용량과 운영 조건

한도는 기록 50개·본문 합계 200만 글자·첨부 50MB, 게시 ZIP 64MB, 서버 전체 보관량 500MB입니다. 실제 운영 업로드는 6MB 가상 첨부로 확인했으며 첨부 50MB·ZIP 64MB 전체를 실전 전송한 검증은 아닙니다. 정적 파일만 복사한 사본은 게시 서버와 게시자 설정을 별도로 준비해야 합니다.

Vercel Hobby의 별도 서비스 할당량이 적용됩니다. 앱의 500MB 검사는 동시에 들어오는 업로드의 용량을 원자적으로 예약하지 못하므로 동시 게시가 많은 운영에서는 저장량 확인과 별도 동시성 관리가 필요합니다.
